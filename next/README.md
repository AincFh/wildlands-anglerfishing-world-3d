## 新增：可驾驶渔船与真正的船钓（NEXT 0.5）

原本只会围绕湖心循环漂移的装饰木船，现由 **独立导航状态机**控制：真实加速、倒车、惯性阻尼、转向、油量消耗、到达湖岸阻挡和顺应现有波浪的船体摇摆与动态尾流。上船后切换到真实跟船摄影机，船不是简单的镜头移动。可通过 W 加速、S 倒车、A/D 转向；触屏使用已有四向按钮。

- **购船与存档**：首次在岸边点击「购买渔船 · 650」解锁，之后可从不同码头再次登船，不会重复收取费用；持久化剩余燃油、累计航程。
- **抛锚船钓**：行驶中禁止投竿；点击「抛锚停船」后引擎停止，恢复钓竿与真实抛投。水面落点按船首方向和投竿力度计算；鱼漂、鱼线、饵料消耗、鱼群上钩与鱼获结算仍使用原有状态机。
- **登陆与燃油**：水域半径大于 45 米的近岸可以抛锚登陆；靠岸还可支付 95 金币将燃油加满。船在无燃油时不会继续接受动力，玩家可通过停泊靠岸补给。游戏数据只通过现有 localStorage 存档，旧存档自动补默认值。
- **性能**：船体使用现有 3D 网格，导航更新不新建网格对象；纯数学物理模块可在 Node 中测试。自动化检查固定步长、碰岸、燃油、停泊以及真实 Chromium/WebGL 船上垂钓。

这是游戏化运动模型，不宣称专业的船舶六自由度水动力学或商业级载具驾驶。

## 自由观鱼视角（NEXT 0.4.1）

顶部新增「**水下观鱼**」按钮：仅在尚未开始抛竿的准备阶段进入。镜头会潜入水面，**动态跟踪真实游动的活体鱼群**，而不是播放预先渲染的视频或静态鱼图；鱼群在周围继续依照自主状态机游动。点击「返回岸上」、空格、Esc 或点击 3D 画面退出水下观测并重新定位岸线，恢复正常钓竿和抛投指示。此模式不会消耗鱼饵，也不能跳过捕获流程。所有页面控件在移动端仍可使用。

真实 Chromium 验收增加从湖岸进入水下、检测实际摄像机深度及 3D 实例、保存观鱼截图、重新回到钓竿可用状态的交互过程。

## 可见水下鱼群 · UNDERWATER SCHOOLING (0.4.0)

真实 3D 湖泊新增 **48 条桌面端 / 20 条移动端** 的低开销鱼群（每条鱼具有鱼种、位置、航向、深度、速度与可恢复生命周期），采用 **两次 InstancedMesh 绘制**，而不是为每条鱼分别创建大量网格。鱼群会环游湖岸、彼此避让、向真实鱼漂下方的饵料聚集，在受到搏鱼干扰时逃窜，并跟随天气、昼夜调整活跃程度和游泳深度。尾鳍分别运动，鱼不会全部像静态模型一样停在原地。

鱼漂附近有实际游鱼时，咬钩会优先选中真实鱼群中的个体，且只能占用一个鱼；上岸后该鱼短暂离开水域并在生态冷却后重新出现，脱钩则放归并逃散。较远位置继续使用既有天气/饵料/水深概率分布生成深水鱼讯。探鱼图现明确分开“生态预测”百分比和附近**可见 3D 鱼群的实测数量**，不再把两者混为一谈。

新增 7 项纯 Node 状态机测试，验证固定种子、真实位置、湖岸边界、群游响应、饵料吸引、逃散、鱼获移除及恢复。真实 Chromium/WebGL 的截图和交互验收会检查 GPU 实例数量、鱼群追踪、鱼漂吸引、搏鱼阶段以及 mobile 轻量化。它是改进中的机制，而不是商业级水生物理、整湖完整生态或高质量动画的完成声明。

# WILDLANDS NEXT · 山野钓行（3D 引擎重建预览）

这是新的 **Three.js / WebGL2** 分支，不再基于旧版手写 WebGL 几何渲染。它与原版游戏分开：旧版入口仍在仓库根目录，新版位于 `/next/`。

## 湖泊生态、探鱼仪与鱼获履历

- **天气、时段驱动的鱼群**：八种鱼根据黎明、日间、黄昏、夜间、降雨、风力、饵料、钓点以及真实落点深度调整活动分布，而非只用天气改变画面色调。
- **统一抽样与探测预测**：顶部「探鱼图」展示三处岸线、等深线示意图与当前环境下主要鱼类的百分比。预测和实际搏鱼调用同一套加权模型，演示概率不是随意编造。
- **鱼获日志**：图鉴新增最近 40 次成功上岸的本地记录，包含鱼种、重量、钓点、饵料、时段、天气和结算收益。旧存档自动兼容，避免重复写入失败抛竿。
- **弹性可视化鱼线**：原有少量刚性线段改成固定 15 个节点，张力收紧、松线下垂、风吹侧摆，使用复用缓冲区避免频繁创建几何对象。属于性能友好的视觉物理近似，不宣称真实绳索动力学。
- **验证**：新增生态概率分布、咬钩延迟、日志限制、鱼线形状单元测试，以及 Chromium 的探鱼图和鱼获日志真实交互截图。

## 3D 鱼体建模与动态游动升级

- 鱼种不再只是同一条鱼的不同颜色：八种鱼具有独立长宽、躯体高度和尾鳍比例。北方狗鱼更细长，鲤鱼较高厚，鲟鱼更长、体态更贴底。
- 实际 3D 几何体拥有绕尾柄旋转的分叉尾鳍关节以及左右胸鳍关节，不再通过整个鱼体持续自转来模拟游动。
- 搏鱼时尾鳍根据时钟和挣扎强度摆动；上岸展示时使用较平缓的尾鳍/胸鳍运动及轻微躯体摆动。
- 动画计算与鱼种比例由 `src/sim/fishMotion.mjs` 提供纯数学驱动，并由 Node 单测和真实 WebGL 浏览器的网格姿态变化验收。
- 仍属于程序化美术资产；此更新提升了轮廓差异与动作逻辑，但不将其描述为商业 3A 模型或真实生物力学仿真。
- **8 项湖泊巡护委托**：鱼种、钓点、重量、深度、使用饵料与物种多样性目标；存档记录进度，完成后手动领取金币，重复领取无效。
- **动态时钟与时段切换**：HUD 按真实游戏世界时间显示；晨光/正午/落日/星夜可循环切换，时段切换后仍保持昼夜自动演进。

## 结构和运行要求

- `src/world/*`：湖面、天气、天空、森林和岸线场景。
- `src/angler.js`：可操作的钓鱼流程、渔具与存档。
- `src/world/fishModel.js`：本地 parametric 鱼体 3D 模型。
- `src/world/shoreDetails.js`：实例化岸边植被/岩石/漂流木。
- `tests/next_browser.py`：真实 Chrome/Selenium/WebGL 浏览器验收。
- `../.github/workflows/next-smoke.yml`：自动化验收及截图产物。

Three.js 运行时现由 **npm 固定版本 0.179.1 构建时打包到本站 `/next/vendor/three/`**，游戏运行**不再依赖外部 Three.js CDN**。仍要求 WebGL2；本地运行需先在仓库根目录执行 `npm install --no-audit --no-fund`、`npm run vendor:three`、`npm run verify:three`，再以 `python -m http.server 8080` 提供本地 HTTP 服务并打开 `/next/`。不能双击 HTML 使用 ES 模块。GitHub Actions 构建、浏览器测试、部署均使用同一固定版本，MIT 许可附带于 vendor 目录。可选外部钓竿 GLB 和树木模型仍受各自服务商网络状况影响，但默认不请求它们。

## GitHub Pages 静态缓存与发布一致性

GitHub Pages 对静态脚本有浏览器缓存。只给 HTML 添加 `?v=...` **不能刷新内部的 ES Module 导入**，这曾造成发布了新的鱼模型，玩家仍收到旧版动作逻辑。现在发布流水线运行 `scripts/version-next.mjs`，把整个 `dist/next/src/**` 依赖图里的相对模块 URL 统一改为当前 Git commit 的固定 `?v=<12位 SHA>`。原始源码保持可读、无发布参数，生产构建和真正的 Chrome/WebGL 验收使用同样的版本化目录。Three.js 自身由于版本锁定并本地化，可继续复用固定依赖缓存。

## 性能与限制

这是**独立重建中的可玩公开预览，不是完成的商业级游戏**。真实鱼模型仍属于程序化造型，并非摄影测量或专业美术师制作的骨骼资产；森林也未达到大型商业 3D 游戏的植被复杂度。软件 GPU 的截图与帧率不能代表独立显卡实测性能。

为避免第三方 GLB 的 CORS 错误，外部树木模型默认禁用。可显式增加查询参数 `externalTrees=1` 尝试加载，但第三方服务器仍可能阻止跨域访问。钓竿外部 CC0 模型同样仅在 `rod=kit` 时尝试；默认使用本地可运行的碳纤维造型。
